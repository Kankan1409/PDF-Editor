# แก้ข้อความบนหน้าโดยตรง — 15 ตุลาคม 2026

อัปเดตแก้ Method Not Allowed: หาก Backend ที่ยังรันอยู่ไม่รู้จัก `/api/apply` (404/405) หน้าเว็บจะใช้ `/preview` ตามด้วย `/commit` ของรุ่นเดิมในเซสชันเดิมโดยไม่มีหน้าต่างเปรียบเทียบ ไม่ retry เมื่อฟอนต์ผิดพลาด, revision เปลี่ยน, server error หรือ network error เพื่อไม่ให้บันทึกซ้ำ การแก้ครั้งนี้ผ่าน frontend tests 16 รายการและ production build; จำลอง HTTP รุ่นเก่าใน tests ยังไม่ได้ทดสอบกับ process ที่ผู้ใช้เปิดอยู่จริง

- เอาหน้าต่างเปรียบเทียบก่อน/หลังและขั้นตอนยืนยันออกจาก UI
- ดับเบิลคลิกข้อความเพื่อพิมพ์บนหน้า; Enter/ปุ่มบันทึกใช้งานแก้ไข, Esc/ปุ่มกากบาททิ้งเฉพาะร่าง
- ใช้ Tab เลือกบรรทัดแล้ว Enter/F2 เพื่อเริ่มแก้ได้; แท็บเล็ตใช้ปุ่ม “แก้ข้อความบนหน้า” ในแถบคุณสมบัติ
- บันทึก PDF จริงผ่าน `/api/apply` ซึ่งตรวจ revision, ฟอนต์, พื้นที่และข้อความอ่านกลับก่อน commit พร้อม Undo/Redo
- ปิดการเปิดไฟล์ เปลี่ยนหน้า ลบ และส่งออกระหว่างพิมพ์ร่าง เพื่อป้องกันร่างหาย บันทึกไม่ผ่านจะเก็บข้อความไว้ให้แก้ต่อ
- การพิมพ์ผ่าน IME ไม่บันทึกเมื่อกด Enter เพื่อเลือกตัวอักษร และป้องกันส่งคำสั่งบันทึกซ้ำ
- การค้นหา/แทนที่และจัดหน้ามีผลทันที ย้อนกลับด้วย Undo ได้

## ผลทดสอบ

- Backend: 27 tests ผ่าน รวม direct apply → export → Undo/Redo, Thai replacement, revision เก่า, invalid edit ไม่เปลี่ยน PDF และ regression ฟอนต์ CI.08 เดิม
- Frontend: 8 component/interaction tests ผ่าน รวม App + text-hit ปุ่มจริง (จำลอง PDF.js และ API), double-click, Enter, Esc, IME, error recovery และไม่เปิด comparison dialog
- Frontend production build ผ่าน
- แก้ browser E2E script ให้ตรงกับ workflow ใหม่แล้ว แต่ยังไม่ได้รันบนเบราว์เซอร์จริง จึงยังไม่ยืนยันภาพหน้าจอ/ตำแหน่งกล่องด้วย browser E2E
- การเปลี่ยน UX ไม่ได้เพิ่ม glyph ที่ขาดในฟอนต์: หาก CI.03 หรือ Resume ใช้ฟอนต์ที่ใช้ซ้ำไม่ได้ ยังแจ้งข้อจำกัดและไม่เปลี่ยนเป็นฟอนต์อื่น ไม่อ้างว่าแก้ข้อความทุกตำแหน่งของสองไฟล์นี้ได้
