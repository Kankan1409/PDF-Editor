# คลังฟอนต์และการเพิ่มฟอนต์

เพิ่ม 82 ไฟล์ static TTF จาก Google Fonts (Sarabun, Kanit, Prompt, Bai Jamjuree, Lato) รวมกับ Noto Sans และ Noto Sans Thai เดิมเป็น 84 ไฟล์ รายการแหล่งที่มา hash และ git blob อยู่ใน `backend/fonts/library-manifest.json` พร้อม OFL ของแต่ละครอบครัว ดาวน์โหลดจาก https://github.com/google/fonts/tree/main/ofl ไม่ใช่ฟอนต์ทุกชนิดที่มีในโลกและไม่ใช่การรับรองว่าฟอนต์ทั้งหมดเป็นฟอนต์ราชการ

## ใช้งาน

1. เริ่ม Backend ใหม่แล้ว Ctrl+F5 เปิด PDF
2. ค่าเริ่มต้นคือรักษาฟอนต์ต้นฉบับ ถ้าต้นฉบับเป็น subset ที่ขาดตัวอักษร เลือก “ฟอนต์สำหรับแก้ข้อความ” ในแถบขวา เช่น Sarabun-SemiBold ซึ่งรองรับไทยและอังกฤษ
3. เลือกก่อนเริ่มแก้ หรือเปลี่ยนขณะที่ยังมีร่างข้อความได้ การเลือกเองจะเปลี่ยนรูปลักษณ์ แต่คงขนาด สี และ baseline ถ้าเนื้อหาพอดีพื้นที่
4. หากต้องการ Anantason เดิม ต้องนำเข้า TTF/OTF ฉบับเต็มของน้ำหนักและชื่อเดิมที่มีสิทธิ์ใช้ ผ่านปุ่ม “เพิ่มฟอนต์ TTF / OTF” แล้วเลือกชื่อที่เพิ่มจากรายการ ไม่ต้องเริ่มเซิร์ฟเวอร์ใหม่

นำเข้าฟอนต์ได้สูงสุดไฟล์ละ 10 MB รวม 30 MB ต่อเซสชัน ไม่เขียนไฟล์ผู้ใช้ลงดิสก์และไม่แชร์กับเซสชันอื่น หายเมื่อปิด/หมดอายุเซสชันหรือเริ่ม Backend ใหม่ สำหรับติดตั้งถาวรให้ผู้ดูแลวางฟอนต์ที่มีสิทธิ์ใน PDF_FONT_DIR แล้วเริ่ม Backend ใหม่

ฟอนต์นำเข้าต้องเป็น static TTF/OTF ไม่ใช่ variable font มีชื่อ PostScript และไม่ตั้งข้อจำกัดการฝังที่ระบบรองรับไม่ได้ ข้อความที่ยาวเกินพื้นที่ ฟอนต์อ่านกลับผิด หรือเอกสารถูกจำกัดสิทธิ์ยังอาจถูกปฏิเสธ ไม่มีการซ่อนข้อผิดพลาดหรือเปลี่ยนฟอนต์อัตโนมัติ

## ผลทดสอบ

Backend 35 tests ผ่าน รวมรายการไทย/อังกฤษ, นำเข้า, ไฟล์เสียหาย, embedding restrictions, แยกเซสชัน และ Resume.pdf จริง: เลือก Sarabun-SemiBold → เขียน “Kanyarat ด” → ส่งออก → อ่านกลับถูกต้อง → Undo คืนไฟล์เดิม ขนาดและ baseline คงเดิม ไม่ได้เพิ่มฟอนต์ Anantason ฉบับเต็มในแพ็กเกจ

Frontend 19 tests ผ่าน รวมเปลี่ยนฟอนต์โดยรักษาร่างข้อความและส่งชื่อฟอนต์ที่เลือกให้ backend พร้อม build ผ่าน ยังไม่ได้ทดสอบเบราว์เซอร์จริงหรือรับประกันรูปลักษณ์ร่างกับ PDF ตรงกันทุกฟอนต์
