# แก้การเปลี่ยนฟอนต์อัตโนมัติ — 14 ตุลาคม 2026

สาเหตุเดิม: insert_line นำ embedded font มาใช้เฉพาะ simple Latin และเปลี่ยนภาษาไทยเป็น Noto เสมอ แม้ใน PDF จะฝังฟอนต์เดิมครบอยู่แล้ว

แก้ไขแล้ว:
- ข้อความไทยใช้ไฟล์ฟอนต์เดิมในการ shaping และนำผลไปวางบน baseline เดิมด้วย translation เท่านั้น ไม่ scale ไม่ synthesize bold/italic
- ตรวจ hash ของ embedded font ในผลจาก shaper เพื่อปฏิเสธ silent fallback
- คง font size เดิมทั้งไทยและอังกฤษ; ใช้พื้นที่ว่างด้านขวาได้เฉพาะก่อนเจอข้อความ รูปภาพ หรือขอบเส้น/ตาราง
- ถ้าข้อความไม่พอพื้นที่ จะปฏิเสธแทนย่ออักษร; ถ้าหาฟอนต์ที่ใช้ไม่ได้ จะปฏิเสธแทนใช้ Noto
- กรณี embedded subset ขาด glyph จะค้น exact PostScript/full font name จากโฟลเดอร์ฟอนต์ของระบบหรือ PDF_FONT_DIR โดยตรวจ embedding bits และ glyph coverage ไม่เลือกฟอนต์ที่เพียงคล้ายกัน
- การเพิ่มข้อความใหม่ยังใช้ Noto ได้ เพราะไม่มีฟอนต์ต้นฉบับให้รักษา

ผล regression: 21 tests ผ่าน รวม font bytes, Thai text readback, size, color, baseline, Tahoma ที่ไม่ใช่ Noto, overflow ขอบตาราง และการปฏิเสธ fallback

ข้อจำกัด: ยังไม่ได้รับ PDF ต้นฉบับที่ปรากฏในภาพของผู้ใช้ จึงยังไม่ยืนยันผลกับไฟล์นั้นหรือ kerning แบบกำหนดเองทุกกรณี ไฟล์ subset ที่ไม่สามารถ map Unicode/shape ได้อาจยังแก้ไม่ได้ แต่จะไม่เปลี่ยนไปใช้ฟอนต์อื่นเอง

เริ่มใช้: ส่งออกงานที่ต้องการเก็บก่อนหยุดเซิร์ฟเวอร์ด้วย Ctrl+C แล้วรันคำสั่งเดิมใหม่ รีเฟรช browser และเปิด PDF ต้นฉบับอีกครั้ง หากไฟล์เคยถูกบันทึกด้วยฟอนต์ fallback แล้ว ต้องกลับไปใช้ต้นฉบับก่อนแก้
